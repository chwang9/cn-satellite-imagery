## 限流与容错

- DataV 对高频请求返回 **403（IP 级临时限流）**，脚本退避重试（5/15/40 s）；
  被封时优先走边界本地缓存。索引走 1 次请求备用源，不级联 370+ 次 DataV（会触发封禁）。
- Esri 瓦片失败按 `--retries`（默认 2）重试；仍失败则该瓦片记为缺失、**用全局均值填充**（不崩溃、不留黑块，
  除非 `--no-fill-holes`）。缺失/纯色瓦片数量写入产物元数据（`failed_tiles` / `blank_tiles` / `filled_holes`）。
## 常见问题 / 排错

| 现象 | 原因与处理 |
|---|---|
| 输入「合肥市」被拒（退出码 3） | v1.3 起区县级护栏：省 / 地级市一律拒绝。改用区县名或 6 位 adcode，或 `download_imagery.py --bbox` 自定义范围（不受护栏限制）。 |
| 影像看着「不像那个地方」 | 多为 v1.5.0 之前缓存的错误瓦片被复用 —— **升级后必须 `--clean-cache`**（或删除 `_tiles/`）再下载。 |
| DataV 返回 403 | IP 级临时限流；脚本已退避重试（5/15/40 s），并优先复用本地边界缓存。 |
| 成品 TIF 体积异常（GB 级） | v1.6.0 前的「创建选项丢失」导致无压缩 + 1 行 strip（2.02 GB vs 229 MB）；用当前版本重跑即可。 |
| 内存吃满 / 频繁换页 | 调小 `--mem-budget-mb`（如 512）走流式路径，峰值内存与面积解耦。 |
| 下载进度长时间不动 | 默认每 2 s 刷新一次（可按 `--progress-sec` 调小）；用 `[n/6]` 阶段提示定位卡点。 |
| `--source google` 全部失败 | Google 国内通常不可达，需代理 / 境外；默认用 `esri`。 |
| 换了 `--source`，出的图却和上次一样 | v1.7.1 前缓存键不含影像源，会**静默复用旧源瓦片**。升级后各源已按 `{source}_` 前缀隔离（esri 沿用旧名以保住缓存）；如曾跨源混用，先 `--clean-cache` 再下。 |
| 只想改标题，不想重下影像 | 直接 `make_map.py <已有.tif> --title "..."`（出图后也会打印这条命令）。 |
| 专题图经纬度看着正常，但影像疑似错位 | 经纬网取自 TIF 自身 geotransform，属于「自证」；必须用**变换无关**方法验证（独立底图 NCC / meanAbsDiff），见维护陷阱 #4。 |
| 开了 `--pdf` 却没有 PNG | v1.7.0 之前的行为（PDF 会替换 PNG）；现为「PNG 主图恒出 + 额外 PDF」。 |
| 小图 / 窄图裁切后没变化 | 概览层请求过多会让整段裁切被静默吞掉；v1.7.0 起 `overview_levels` 按尺寸自适应（最短边 ≥ 64 px）。 |
| 图例被红线压住 | v1.7.4 起图例**固定右下角** + 白色面板默认全不透明，红线在框内 0 像素（包河区实测，该区区界确实斜穿右下角）；想让面板半透明透出底图用 `--panel-alpha 0.9`（此时红线会留下约 5% 残影 —— alpha 越低越明显）。若宁可挪位置也不要面板，用 `--legend-pos auto` 走避让评分。 |
| 比例尺看着「不准」 | 先分清两件事：① **尺长真值**由 `_m_per_deg_lon`（WGS84 椭球，尺子所在纬度）决定，v1.7.3 实测偏差 ±0.000%；② **标注位置**现在是逐刻度居中，可直接对格。若感觉「横竖手感不一致」，那是 plate carrée 的固有性质，见维护陷阱 #12。 |

## 自检方式（改动后建议这么验）

1. **静态**：AST 查未使用 import / 无初值的 `global` 名。
2. **Probe**：针对每个可疑点写一个最小复现脚本，**先看修复前的行为**，修完再跑一次对照。
   **「不报错但结果不对」的缺陷优先排查** —— 它们不崩溃、不报错，只是「流程走完了、结果不对」，
   最难察觉（v1.5.0 / v1.5.1 / v1.6.0 / v1.7.0 修的都是这一类）。
3. **离线自测**：桩 session（确定性内容，由 tile URL 派生）+ 足够小的 `--mem-budget-mb`
   逼出流式路径，对比两条路径是否逐像素一致（正确做法应当是 **max diff 0**）。
4. **端到端**：走真实缓存跑一遍完整管线，与上一版产物做窗口抽样对比，确认 **max diff 0** 再替换。

两个常用手段：

- **`--version` 冒烟**：改完 CLI 用 `$PY $S/download_imagery.py --version` 之类跑一遍三个入口，
  确认没有被必填参数挡下（维护陷阱 #9）。
- **未使用 import 用 AST 静态查**（收集 `ast.Name` / `ast.Attribute` 根名的使用集合，
  与 import 名做差集），比肉眼可靠。

## 注意

- **坐标系选择**：默认 3857 是 Esri 瓦片原生投影，拼图零重采样、画质最佳，也是 Web/三维地图标准。
  若需与 `cn-dem`（EPSG:4326）叠加，用 `--epsg 4326`，会做一次双线性重投影（略有插值）。
- **缩放与体量**：zoom=18 对区县约数千~数万瓦片，下载量数百 MB、文件可达数百 MB~GB。
  **省/地级市已被区县级护栏硬拒绝**（见上节），无需担心其高 zoom 触发海量下载；bbox 模式请自行把控范围。
- **GCJ-02 偏移**：DataV 边界是 GCJ-02，已反算为 WGS84，与 Esri（WGS84 底图）对齐，
  不会差几百米。
- **导出/打包前**：删掉 `scripts/__pycache__/`（若有）、`_tiles/`、`_boundary/`、`_adcode_cache.json`
  可减小体积。本技能目录结构为 `SKILL.md` + `scripts/*.py` + `references/*.md`（WorkBuddy 标准结构），缓存目录已是平铺。

### 维护陷阱（踩过的坑，改代码前先看）

1. **`ds.meta` 不含创建选项**：rasterio 的 `DatasetReader.meta` 实测只有
   `count / crs / driver / dtype / height / nodata / transform / width` 八个键 ——
   **compress / tiled / photometric / blockxsize / interleave 全都不在里面**。
   任何「读出来再写回去」的环节（裁切、重投影）都必须用 `_creation_options()` 显式补上，
   否则成品会静默退化成「无压缩 + 1 行 strip」（曾导致 2.02 GB vs 本应 200 MB）。
2. **`ds.compression` 是枚举不是字符串**：返回 `Compression.jpeg`（`.value == 'JPEG'`），
   直接和 `'jpeg'` 比较恒为假 —— 会让依赖它的分支静默失效。
3. **`mercantile` 的 `{y}` 是 XYZ 行号**（y=0 在最北），Esri/Google 都是 XYZ，`flip` 必须为 False。
   历史上 `flip=True` 曾把「瑶海区」取到南纬 32° 的西澳小麦带。
4. **专题图的经纬网来自 TIF 自身 geotransform**，所以地理参考错位时光看专题图完全正常 ——
   验证必须用「变换无关」的方法：拿独立底图做逐像素比对（NCC / meanAbsDiff）。
5. **`DrawingArea` 用数学坐标（y 向上）**，画指北针时北 = `cy + R`，按屏幕坐标写会上下颠倒。
6. **概览层数必须按输出尺寸算**：`build_overviews([2,4,8,16,32,64])` 对小/窄图会抛
   `Too many overviews levels of 1x1 dimension were requested`；在 `_crop_to_bbox` 里这个异常
   会让**整段裁切**被 except 吞掉（「不报错但没裁切」）。一律用 `overview_levels(w, h)`。
7. **别用「模块级 global」传递主参数**：`_crop_to_bbox` 曾依赖 `_REQUEST_BBOX` 且**没有模块级
   初值**，独立调用时 `NameError` 被 try 吞成静默 no-op。函数要什么就显式传什么。
8. **写自测时注意「假通过」**：用随机内容 + 两个不同 cache 对比「两条路径一致性」，测出来的
   是随机噪声而不是回归；且内存预算要给得够小，**否则根本没触发流式路径**（两条其实跑同一条）。
9. **`--version` 要排在必填参数校验之前**：argparse 的必需 positional/option 会在
   `--version` 分支执行前就报错。
10. **缓存键必须区分影像源**（v1.7.1 修复）：瓦片缓存名曾恒为 `{z}_{x}_{y}.jpg`，先用
    `--source esri` 下载、再换 `google` 会直接命中 esri 的瓦片 —— 不报错、不重下，但内容
    是错的。现 `tile_cache_path` / `read_cached_tile` 均带 `source` 参数；esri 沿用旧命名
    （避免 7812 张缓存全部失效重下），其余源加 `{source}_` 前缀。新增影像源时务必走
    `SOURCES` 注册表并把 `source` 透传下去。
11. **图内装饰件的位置要固定；遮挡问题用「面板」解决，不要靠挪位置**（v1.7.4 定调，
    推翻了 v1.7.3 的做法）：v1.7.3 曾让图例按区界压力在 8 个锚点间自动漂移 —— 结果是同一
    套参数下，不同区县的图，图例位置不一样（包河区跑左上、瑶海区留右下），系列配图不一致，
    用户明确要求「比例尺固定左下角、图例固定右下角」。**正解**：位置写死（`SCALE_BAR_X0/Y0`、
    `_legend_anchor("se")`）+ 各垫一块白色面板（`_draw_panel`），让**面板去遮挡**红线。
    面板矩形的取法：不写死尺寸，而是由内容实际占位反推（比例尺面板左右各留出首末标注半宽
    `0.62em×字数/2 + PANEL_PAD_PT`，上留标注行高、下留刻度伸出量），否则调面板尺寸常量、
    字号或分段数时标注会被面板切边。
    panel 的 `zorder` 要**显式**分层，且两块面板都**高于**区界线（白衬 3 / 主线 4）：
    比例尺面板 3.5（低于自身内容 5~8）、图例面板 20（低于自身内容 21~22）—— 这是有意为之：
    红区界线穿到卡片处就被卡片压住，正是「图例不与边界重合」的实现方式。**v1.7.7 前的注释
    把它写反了**（称「比例尺面板在区界线之下（4）」），实际靠「同 zorder 后画者在上」的插入
    顺序才达到覆盖效果；现改为显式 `zorder=3.5`，不再依赖插入顺序。
    避让评分（`_place_legend` / `_boundary_pressure` / `_seg_rect_hit`）保留为 `--legend-pos auto`
    可选路径，不再是默认。改图例尺寸或新增装饰件时，若走 auto 仍须同步登记预留区。
12. **面板不透明度不能用「差不多能压住」的值**（v1.7.4）：`alpha=0.94` 时红线在面板下仍留
    Δ≈(2,14,15) 的偏白量 —— 在整片纯白面板上能看出一条淡粉细线。要「图例不与边界重合」就
    必须 `alpha=1.0`；因此 `PANEL_ALPHA` 默认 1.0，透明是**可选项**（`--panel-alpha`）而非默认。
13. **EPSG:4326 渲染是 plate carrée，水平/垂直地面尺度天然不等**（不是 bug，是性质）：
    经度 1° 在 31.6°N 只有纬度 1° 的 cosφ ≈ 0.851 倍。因此 ① 图幅在屏幕上相对真实地物
    **横向被拉长 ~1.17×**；② 一个**水平**直线比例尺只对水平方向成立（读数本身精确），
    沿垂直方向量同一段会差 1/cosφ。要消除该差异必须改用等角/等距投影渲染（如 UTM），
    但那会牺牲「经纬网为真经纬度网格」这一特性 —— 现有取舍是保留 plate carrée + 精确水平
    比例尺，并在文档里写明。
14. **比例尺真值别用球面近似，也别用图幅中纬**（v1.7.3 修复）：旧代码 `111320·cos(lat_mid)`
    两处偏差叠加后约 0.2%（5 km 尺实际 5011 m）。正确做法：`N = a/√(1−e²sin²φ)`、
    `米/度 = N·cosφ·π/180`，且 φ 取**尺子自身所在纬度**（`south + (north-south)·SCALE_BAR_Y0`），
    而不是图幅中纬。改 `SCALE_BAR_Y0` 高度时必须同步这里的纬度取样。
15. **⚠ blended transform 下 x 宽度必须用数据单位，别用 axes 分数**（v1.7.4 引入、v1.7.5 修复）：
    比例尺条带用 `blended_transform_factory(ax.transData, ax.transAxes)` 绘制（x 数据、y 分数），
    所以 `Rectangle(..., width, ...)` 的 `width` 是**经度差**。v1.7.4 重构时把外框/白衬两处的
    `width_deg` 误写成 `width_frac`，二者相差 `(east-west)` 倍（包河区图幅 ≈ 3.9×），条带外框
    被画成 0.206 **度** ≈ 19.5 km —— 表现为「比例尺从面板右侧突出去一大截」。**迷惑点**：分段
    (`seg_w = width_deg/nseg`) 和刻度标注都用的是正确值，所以黑白块端点、数字、面板全是准的，
    只有首尾两个矩形（白衬 + 黑外框）错 —— 单看数字/量黑白块永远测不出来，**必须量外框**。
    教训：同一个函数里同时存在 `width_frac`（面板块用）和 `width_deg`（几何用）时，命名要
    显式区分（现为 `width_frac` / `bar_w`）并在赋值处写明单位。
16. **卡片的几何必须由「实测包围盒」反推，不能用字号估算**（v1.7.6）：白色衬底面板（比例尺/
    图例背后的卡片）曾用 `0.62em × 最宽标签字数 ÷ 2 + pad` 估留白。三个隐患：① 这是**估算**，
    换字体/字重/字号后不再成立；② 左右各加 `max(0.0, ...)` / `min(1.0, ...)` 会把矩形**夹到
    图幅边界** —— 一旦 `SCALE_BAR_X0 - pad_x < 0`，卡片左沿变 0，内容就露在卡片外（正是用户
    报的「超出背景卡片」）；③ 加 `clip_on` 默认裁剪后更看不出来。
    **正解**：先把图元全部画出来，再用 `get_window_extent(renderer)` 取**实测渲染包围盒并集**
    + `PANEL_PAD_PT` 得到矩形（`_artists_bbox_axes()`）—— 卡片永远包住内容，与字体无关。
    文字宽度也用真实字体实测（`_measure_max_half_width_pt()`，临时造 Text 量完即删）。
    另外**必须保证卡片能塞进图幅**：水平空间不足时先右移条带，再按 `_SB_SHRINK_TARGETS`
    缩短条带目标长度（迭代 ≤3 轮，因为缩短会改变标注宽度），否则卡片被裁、内容照样外露。
    同理适用于任何「给内容加背景卡片」的需求（图例、注记框、图廓）。
    验证方式：断言「卡片 ⊇ 全部图元包围盒」且「卡片 ⊆ 图幅 [0,1]」，并在多图幅×多图形尺寸
    下跑参数化测试（当前 24 组合全通过）。**注意**：用像素扫描 PNG 反查卡片边界会被底图暗像元
    干扰（窗口里到处是深色地物），要定位卡片请认灰边框 #8c8c8c，或直接在 artist 层断言。
17. **面板尺寸与字号必须同源于「图幅」，不能一个写死 axes 分数、一个是固定磅值**（v1.7.7 修复，
    用户反馈「图例怎么超出了背景卡片」）：图例框曾写死 `LEGEND_W/LEGEND_H = 0.27/0.056`（axes
    分数，**图幅无关**），文字却是固定 `fontsize=9.5/8.8`（磅值，**图幅无关**）—— 但 1pt 折合的
    axes 分数会随轴宽变化。探针实测：轴宽 8.76in 时余量 0，6.80in 溢出 0.09in，5.30in 溢出
    0.14in，3.40in 溢出 0.68in —— 图幅越小，文字越必然顶出白框。
    **正解**：① 版式常量按**英寸**标定（`LEGEND_*_IN`），再除以轴宽/轴高得 axes 分数；② 字号
    随轴宽在 `LEGEND_SCALE_RANGE` 内等比缩放；③ 面板尺寸取 `max(LEGEND_MIN_*, 实测需求)`，
    实测需求由临时 `Text` 的 `get_window_extent()` 量真字宽得到（`_legend_metrics()`）。
    附带兜底：极窄图幅下图例会变宽、可能横向压到左下角的比例尺卡片 —— 把图例**整体抬高**
    （`dy = scale_rect[3] + LEGEND_MARGIN - rect[1]`）而不是挪到别的锚点，保住「右下角」语义。
    验证方式：多图幅（轴宽 3.4~10.3in）× 多锚点共 80 组，用 artist bbox 并集断言「内容 ⊆ 面板」。
18. **凡「写死的边距/尺寸」都要问一句「极端输入下还够吗」；凡「失败判据」都要问一句「可达吗」**
    （v1.7.7 两个同源教训）：
    - **标题栈上边距写死**：`TOP_IN = 0.5` 英寸。`--max-side 3500 --dpi 100`（`img_w_in ≈ 35`）
      时 14pt 主标题 + 副标题需 ~0.558in > 0.5in，标题被图幅上沿**静默裁掉**（不报错、不警告）。
      正解：`_title_layout()` 用实测文字宽（`_fit_text_fs()` 收字号）与行高**反推**上边距。
      阈值：字号 `TITLE_FS_RANGE/SUBTITLE_FS_RANGE` 随图宽插值，下限 `TITLE_MIN_FS=6.0`。
    - **下载器「全部失败」判据不可达**：`if n_fail == n:` 永远为假 —— 因为首张瓦片由「影像源
      可达性探测」阶段取回，失败会直接 `SystemExit`，所以 `n_fail` 最多 `n-1`。这条分支里
      「产物是占位灰图，请检查网络」的告警**形同虚设**。正解：按「真正拿到统计均值的瓦片数」
      判定（`n_ok = sum(1 for t in tiles if stats.get(t) is not None)`，`n_ok == 0` 才用中性灰），
      并补一条「除首张探测瓦片外全失败」的次级告警。
    教训：写 `==` 判据时先枚举变量的**取值范围**；写 `x = 常量` 时先想**什么输入会让它不够**。
19. **`PYTHONDONTWRITEBYTECODE` 运行时设置无效 —— 必须改 `sys.dont_write_bytecode`**（v1.7.7，
    与 #8 的「假通过」同类）：CPython **只在解释器启动时**读 `PYTHONDONTWRITEBYTECODE` 来初始化
    `sys.dont_write_bytecode`，脚本运行到一半再 `os.environ[...] = "1"` 不起任何作用。表现有二：
    ① 直接执行的脚本本就不写 `__pycache__`，所以「没看到 .pyc」是**假通过**，会掩盖问题；
    ② 被 `import` 的同级脚本（如 `satellite_imagery_cn.py` → `download_imagery.py`）**仍会**生成
    `scripts/__pycache__/` —— 而技能目录只允许两级结构，多出的缓存目录会污染交付物。
    正解：每个脚本头部直接 `sys.dont_write_bytecode = True`（四个脚本现已全部加上）。
    自检：`python -c "import download_imagery"` 后 `ls scripts/__pycache__` 应为不存在。
    **v1.7.8 补记**：v1.7.7 只加了 `sys.dont_write_bytecode = True`，却**把
    `os.environ[...] = "1"` 那行留在了原地** —— 于是一段「说明它无效」的注释下面紧跟着一行
    无效代码，成了自相矛盾的死代码（真正生效的一直是下一行）。改完这类问题要顺手确认
    **被替换掉的旧写法是否已删除**，而不只是新增正确写法。
20. **优化前先量「占比」，否则容易把力气花在 2% 上；放弃项也要有数据**（v1.7.8）：
    出图链路的实测分解（包河区 z17，`--max-side 2600 --dpi 200`，各阶段单独计时）：
      · `load_display_array`（降采样读 + 重投影） 1428 ms → **56%**
      · `_render_map_core`（比例尺/图例/标题/指北针/经纬网/边界**全部**装饰件） 50 ms → **2%**
      · `savefig`（Agg 渲染 563 ms + PNG 编码 439 ms） 1080 ms → **42%**
    **光看代码只会觉得「装饰件逻辑最复杂 = 最值得优化」，实测只占 2%** —— 想提速只有读图
    与存盘两条路。据此 v1.7.8 只动了两处：
      · **降采样读的核 `bilinear` → `average`**（1420 → 1004 ms，**1.41×**）。降采样 4.9× 时
        bilinear 只取 2×2 邻域、不覆盖像元足迹 → 必然混叠；average（面积平均）才是正确核。
        同一次改动**既更快又更对**。注意**只改降采样那一跳**，跨 CRS 的 `reproject` 保持
        bilinear（它不是同轴降采样）。
      · **PNG 存盘 zlib 级别 6 → 3**（1123 → 1002 ms，**1.21×**，**体积一模一样、逐像素差 0**）。
        高熵影像上 zlib 级别对压缩率几乎无影响，但耗时差得出来。不再降到 1：再快约 9%
        但体积 +25%。
    **放弃项同样要有数据**（否则「没做」和「没想到」分不清）：
      · GCJ-02→WGS84 向量化 —— 包河区边界只有 **282 个顶点**，全量 0.54 → 0.09 ms，
        只省 0.45 ms，不值得引入数值一致性风险。
      · `rasterio.vrt.WarpedVRT` 直读 —— 实测 **7018 ms**，比现路径 1458 ms **慢 4.8×**，
        且目标网格要自己重算（实测长宽比还会错）。
      · `--supersample` 默认 2.0 → 1.0 —— 读图快 3.2×（1476 → 467 ms），但**改变所有产物
        观感**，属默认行为变更，不擅自改；留给用户显式传参。
    教训：**「更复杂」不等于「更热点」**。把 `time.perf_counter()` 打在阶段边界上，
    五分钟就能避免一整天白干；改动之后也要用**同一脚本内的 A/B** 报数，别跨会话比不同负载。
