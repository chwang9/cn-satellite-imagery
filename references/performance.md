## 出图性能分解（v1.7.8 实测；先测量再决定优化哪儿）

样本：包河区 z17 成品（23943×29724 px / 285 MB），`--max-side 2600 --dpi 200`。
各阶段单独计时：

| 阶段 | 耗时 | 占比 |
|---|---|---|
| `load_display_array`（降采样读 + 重投影） | 1428 ms | **56%** |
| `_render_map_core`（**全部**装饰件：比例尺/图例/标题/指北针/经纬网/边界线） | 50 ms | **2%** |
| `savefig`（Agg 渲染到 buffer 563 ms + PNG 编码 439 ms） | 1080 ms | **42%** |

> **结论：装饰件的绘制成本可忽略（2%）。** 想提速只有「读图」与「存盘」两条路 ——
> 这也是 v1.7.8 完全没有改动比例尺/图例/标题版式代码的依据（改了也没用）。

### v1.7.8 的两项优化（同一脚本内 A/B 对照）

| 优化 | 前 | 后 | 提升 | 代价 |
|---|---|---|---|---|
| 降采样读的重采样核 `bilinear` → `average` | 1420 ms | **1004 ms** | **1.41×** | 与旧产物像素差 mean 0.31 / p99 2 / max 7（/255）；且 **average 是降采样的正确抗混叠核，bilinear 在 4.9× 降采样时有混叠** —— 属「更快且更对」 |
| PNG 存盘 zlib 级别 6 → 3 | 1123 ms | **1002 ms** | **1.21×** | **体积完全不变**（18.56 MB）、产物**逐像素差 0** |

端到端：同参数出图 **2.8 s → 2.2 s（约 −21%）**；同参数产物逐像素差 mean 0.243 / p99 2
（差异>2 的像素占 0.303%），全部来自新的 average 核。

### 评估后**放弃**的优化（有数据才敢放弃）

| 候选 | 实测 | 放弃理由 |
|---|---|---|
| GCJ-02→WGS84 向量化 | 包河区边界只有 **282 个顶点**：0.54 ms → 0.09 ms | 绝对收益 **0.45 ms**，不值得引入数值一致性风险 |
| `bbox_of_geometry` 优化 | 0.6 ms/次（每次 resolve 只调一次） | 同上 |
| 用 `rasterio.vrt.WarpedVRT` 直读替代 read+reproject | **7018 ms**，比现路径 1458 ms 慢 **4.8×** | 更慢，且目标网格要自己重算（实测长宽比还会错） |
| 优化装饰件绘制 | 仅占出图总时长 **2%** | 无可优化空间 |
| PNG 级别继续降到 1 | 再快约 9% | 体积 18.56 → 23.13 MB（**+25%**），不划算 |
| `--supersample` 默认 2.0 → 1.0 | 读图 1476 → 467 ms（**3.2×**） | 属**默认行为变更**（所有产物观感改变，mean 2.8/255），不擅自改；需要时用户自行 `--supersample 1.0` |
| 拆分 `build_mosaic`（188 行 / 38 分支，全仓最复杂函数） | — | 收益只是可读性，而它是核心下载路径，回归风险高；暂不动 |

## 下载与拼接性能（v1.6.0 实测基线）

基准样本：瑶海区 z17 成品 `15721×32039`（2.02 GB）、Windows / 16.9 GB 内存。
所有数字都是**微基准实测**，不是估计值。

| 环节 | 优化前 | 优化后 | 提升 |
|---|---|---|---|
| 成品 TIF 体积 | **2024.9 MB**（无压缩 + 1 行一条 strip） | **229.3 MB**（jpeg q90 + 256 分块） | **8.8×** |
| 专题图影像读取 | 3.47 s / 进程峰值 1002 MB | 1.22 s / 进程峰值 174 MB | **2.8×** / 内存 **5.8×** |
| 整条出图（`make_map`，300 DPI） | 4.9 s | **2.8 s** | **1.75×** |
| 瓦片解码数组常驻内存 | 7812 张 ≈ **1.8 GB**（z18 的 21630 张 ≈ 4.2 GB，会换页） | 按预算流式，≈ 线程数 × 0.2 MB | **与面积解耦** |

**专题图 `--supersample` 权衡**（同一输出网格，仅改源读取的降采样倍数）：

| supersample | 读取耗时 | 与旧「整幅物化」路径的像素差 |
|---|---|---|
| 1.0 | 0.70 s（4.9×） | mean 2.8 / p99 14（/255） |
| **2.0（默认）** | **1.22 s（2.8×）** | mean 1.5 / p99 7 |
| 旧路径（整幅物化后单次重投影） | 3.47 s | 基准 |

> 注：旧路径是「从全分辨率源做 8× 抽取的 bilinear」，本身有混叠，并不是更优基准；
> 新路径走建概览时用的 `average` 金字塔，抗混叠更好。`--supersample 1.0` 最快，需要
> 极致贴近全分辨率观感时可调大。

## 交互（v1.6.0 起；v1.7.0 修 100% 帧）

长任务最怕「看不出在动」。现在的行为：

- **阶段提示**：`[1/6] 规划 → [2/6] 影像源可达 → [3/6] 并发下载 → [4/6] 拼接写入
  → [5/6] 概览金字塔 + 裁切 → [6/6] 完成`，每步带用时。
- **下载进度按时间刷新**（`--progress-sec`，默认 2 s，不再固定「每 500 张」）：
  `下载 3200/7811 (41.0%)  86.3 张/s  已用 37s  剩余≈54s`；并汇总**缓存命中数**。
  【v1.7.0】此前判据写成 `done == n`（而 futures 只有 `n-1` 个），**100% 那一帧永不打印**；
  现已修正，真实跑会收尾在 `下载 7811/7811 (100.0%)  881.1 张/s  剩余≈0s`。
- **`--version` 三个入口都可直接查看**（v1.7.0）：此前 `--bbox`/`input` 等必填项会先触发
  argparse 报错，版本打不出来。
- **`--dry-run` 预检**：先看「多少张瓦片 / 块多大 / 像元多少 MB / 会不会超限」，再决定下不下。
- **结束给下一步**：出图后会打印「复用 TIF 重渲染」的命令，避免为了改标题重下影像。

真实端到端样例（瑶海区 z17，7812 张全部命中缓存，用时 1m05s）：

```
[预检] 预检 zoom=17: 瓦片 7812 张 → 块 15872x32256 px，像元约 1536 MB
[1/6] 规划: 瓦片 7812 张 … 内存策略 = 全量留内存（约 1536 MB）
[3/6] 并发下载 7811 张（12 线程）…
  下载 7811/7811 (100.0%)  881.1 张/s  已用 9s  剩余≈0s
  下载阶段完成：用时 9s，缓存命中 7812/7812
[4/6] 拼接写入…   写入完成，用时 8s
消拼缝完成（feather=24px，处理 61 条纵缝 / 125 条横缝）
[6/6] 全部完成，总用时 1m05s
```

```bash
# 只看不下：预检瓦片数与体量
$PY $S/satellite_imagery_cn.py 瑶海区 --zoom 17 --dry-run
$PY $S/download_imagery.py --bbox "117.28,31.85,117.32,31.89" --zoom 17 --output x.tif --dry-run
# 想省内存（例如同时开别的程序）：把预算调小走流式
$PY $S/satellite_imagery_cn.py 瑶海区 --mem-budget-mb 512
```
